# scripts

开发期辅助脚本，不参与应用构建，可随手删除或扩展。

## verify-i18n-coverage.js

校验 `frontend/src/i18n` 语言包与代码中翻译调用是否对齐。

```bash
node scripts/verify-i18n-coverage.js
```

退出码：静态缺失为 0（`$t` 调用命中了不存在的 key）时返回 1，否则返回 0，可直接挂到 CI。

### 校验项

1. **静态缺失** —— 代码里 `$t('a.b.c')` 用到但语言包没有定义。运行时表现为界面直接显示 `a.b.c` 字面量。
2. **静态冗余** —— 语言包定义了但代码中无静态引用。注意其中一部分是经 `labelKey` 之类变量间接寻址的，属正常，见第 4 项。
3. **双语对齐** —— 对比 `.zh` 与 `.en` 分片的 key 集合。zh 有 en 无时，切到英文界面会静默回退显示中文。
4. **动态调用清单** —— `$t(key)` / `$t(\`admin.words.cat.\${k}\`)` 这类拼接调用静态无法判定命中，单独列出供人工确认。

### 解析方式

语言包是纯嵌套对象（无数组、无模板字符串值），脚本用词法解析而非按行正则：`stripComments` 先剔除注释避免示例文案被误采，`parseObject` 递归解析 `export default` 对象字面量，`flatten` 展开成 vue-i18n 实际查找用的点号完整路径。

调用侧匹配用后行断言 `(?<![\w$.])` 只保留 `$t(` / `i18n.global.t(` / 裸 `t(`，排除 `import(`、`mount(`、`emit(`、`setTimeout(` 这些以 `t(` 结尾的普通函数 —— 早期版本没做这层区分，把模块路径和 CSS 选择器当成了翻译 key。

### 当前基线（v0.4.8，2026-10-19）

| 项 | 数值 |
| --- | --- |
| 语言包分片文件 | 14 个 |
| 展开后完整 key | 872（zh 872 / en 872，双语对齐） |
| 静态调用命中 | 808 个，**零缺失** |
| 静态无引用 | 64 个（经 `labelKey` / `cat.${k}` 间接引用） |
| 动态调用点 | 12 处，集中在 `AdminLayout`、`ReportManage`、`SensitiveWordManage`、`TestManage`、`serverMsg` |

0.4.7 提交说明里的"806 key 全命中零缺失"结论成立；806 应为按命名空间计的使用 key 数，展开到完整路径后静态调用为 808，语言包总数 872。

### 新增文案时的注意事项

- 分片文件按业务域划分（`dashboard` / `flow` / `shell` / `admin` / `expert` / `core`），`.zh` 与 `.en` 必须成对修改，否则第 3 项校验会报差异。
- `i18n/index.ts` 是构建期静态合并，新增分片要同步加 import。
- 尽量避免新写动态拼接 key，会削弱本脚本的校验能力；确有枚举场景时，把候选 key 显式列成数组再索引。
