## Features

### User

| Feature | Description |
| --- | --- |
| **AI Counseling** | Streaming chat (SSE, character-by-character), a gentle and non-judgmental space to talk; **RAG long-term memory** remembers your situation and preferences across sessions, viewable and deletable in the UI for full privacy control |
| **Real-time Translation** | AI replies translated sentence by sentence as they stream in (bilibili Index-Translate, 32 languages), with side-by-side source / translation reading |
| **AI-powered Assessment** | Pinned entry; questions are generated by AI on the fly (different every time), AI holistic scoring (0-100) with graded interpretation; questionnaires and answers fully persisted |
| **Scale-based Assessment** | Classic psych scales with automatic scoring, graded reports and history; admins maintain the question bank |
| **Periodic AI Reports** | Structured analysis over a chosen period of chats and assessments, exportable as HTML; **32-language translation** (Markdown layout preserved) |
| **Expert Booking & Chat** | Book a psychological expert, real-time private chat over Socket.IO (online status / read receipts / offline alerts); status changes sync instantly |
| **Chat Reporting** | Select the other party's messages and file a report; admins verify and enforce (mute / ban) |
| **Session Management** | Multiple sessions with grouping, AI auto-titled summaries, session locking against accidental deletion, paginated history |

### Expert

| Feature | Description |
| --- | --- |
| **My Profile Card** | Edit name / title / specialty / bio (**bilingual zh & en**), goes live after admin review |
| **Booking Management** | Confirm / decline / complete bookings, status broadcast to the user in real time |
| **Counseling Chat** | One-on-one real-time chat with booked users; users see a public expert info card (no private data) |
| **Custom Questionnaires** | Experts create their own scales; after admin review they go live **platform-wide** (new in 0.6.0) |

### Admin

| Feature | Description |
| --- | --- |
| **User Management** | CRUD, role assignment (user / expert / admin), account-restriction status display |
| **Report Enforcement** | Verify reports and act in real time: mute / ban (24h / 72h / 7d / permanent); bans kick the user offline immediately and lift automatically on expiry; only the latest enforcement record carries the lift button |
| **Profile Card Review** | Publish / unpublish expert profile cards |
| **Sensitive Words** | Visual maintenance of the moderation lexicon (full words / substrings, categories); additions and removals take effect instantly, no restart |
| **Scale & Questionnaire Review** | Scale question-bank maintenance + review of expert-created questionnaires |
| **Master Key** | Admins unlock any locked session with a password |

Content safety uses **two-layer moderation**: a sensitive-word lexicon (120+ entries covering homophones, character-splitting and abbreviation variants) intercepts in milliseconds, then AI semantic re-check identifies veiled harassment in context (fail-open when the AI service is down, and only approved verdicts are cached to avoid verdict-poisoning).

### Desktop

| Feature | Description |
| --- | --- |
| **QQ-style Tray Alerts** | Red unread badge (1-8 numeric / 9+ capped) + alternating icon blink + hover message card (DWM bitmap, follows light/dark theme, click to jump into chat) |
| **Taskbar Integration** | Orange taskbar flash on background messages + title preview + hover thumbnail turns into a message card; auto-restore on focus; multi-channel delivery notifies only once |
| **Three-state Theme** | Light / dark / follow system; tray cards adapt to taskbar theme |
| **Full Bilingual UI** | One-click zh / en switch (897 i18n keys covered); tray and notification system text follows along |
| **Global Shortcut** | `Ctrl+Alt+H` to summon / hide from any screen (including lock screen and tray background); browser-style shortcuts auto-suppressed against accidental triggers |
| **Dual-source Auto Update** | Gitee + GitHub checked concurrently with automatic failover to the highest version; on a new release the user decides whether to download, with a live progress bar and cancel support |
| **Privacy Protection** | One-click lock screen / auto-lock on leaving; lock state persists across restarts; local credentials encrypted with AES-256-GCM |

### Security

- **Local data encryption**: sessions and configs stored AES-256-GCM encrypted (Rust side), key compiled into the binary
- **Session security**: JWT + Redis session mapping, single sign-on (new login kicks the old session); logout / lock screen is a true server-side invalidation (token blacklist)
- **API permissions**: three-level role RBAC (user / expert / admin) + middleware double checks; chat reads/writes and room joins are verified against appointment ownership
- **Trusted parameters**: message sender and receiver are derived server-side from the appointment relation; client identity fields are never trusted
- **Key security**: user-supplied model API keys stored AES-256-GCM encrypted; the API only ever echoes the last 4 characters

## Quick Start

### Requirements

Node.js >= 18 · MySQL >= 8 · Redis (optional for local dev, required in production)

### 1. Initialize the Database

```bash
mysql -u root -p < backend/db/schema.sql
```

> The script creates all tables and ships one sample scale (self-rating mood, simplified PHQ-9). After registering an admin account, set `users.role` to `3` in the database.

### 2. Configure and Start the Backend

```bash
cd backend
npm install
cp .env.example .env    # adjust database / Redis / AI key settings
npm run dev             # dev mode (tsx watch), default port 3001
```

Production:

```bash
npm run build && npm start   # runs dist/index.js
```

### 3. Start the Frontend

```bash
cd frontend
npm install
npm run dev          # browser dev preview (Vite)
npm run tauri:dev    # desktop dev mode
npm run tauri:build  # build the desktop app
```

The frontend points to the backend via `VITE_API_BASE` and `VITE_SOCKET_URL` in `.env.development` / `.env.production` — no code changes needed.

## Development

### Project Structure

```
AIHeartHealProject/
├── frontend/                 # Desktop client (Vue 3 + Tauri 2)
│   ├── src/
│   │   ├── api/              # API layer (axios interceptors / session-expiry markers)
│   │   ├── views/            # Pages (dashboard / tests / expert / admin)
│   │   ├── components/       # Shared components (model config / lock screen / date picker / icons)
│   │   ├── stores/           # Pinia (user session / settings / loading)
│   │   ├── router/           # Routes and login guards (role-based)
│   │   ├── i18n/             # zh/en locale packs (six shard files merged statically at build time)
│   │   ├── utils/            # Notifications / taskbar / updater / report rendering / encrypted storage
│   │   └── config.ts         # API_BASE / SOCKET_URL
│   └── src-tauri/            # Tauri shell (Rust)
│       ├── src/main.rs       # Tray badge / DWM cards / update download / encryption
│       └── windows/xinyu.iss # Inno Setup installer script
└── backend/                  # Server (Express + TypeScript)
    ├── src/
    │   ├── index.ts          # Entry: HTTP + Socket.IO
    │   ├── routes/           # users / auth / tests / ai / expert / admin / moderation / memory
    │   ├── middleware/       # JWT auth / unified error handling
    │   ├── db/               # MySQL pool / Redis
    │   └── utils/            # AI client failover / RAG memory / translation / moderation / restrictions
    └── db/schema.sql         # Schema script (includes a sample scale)
```

### Database Design

15 tables (see `backend/db/schema.sql`):

| Table | Purpose | Table | Purpose |
| --- | --- | --- | --- |
| `users` | Accounts & roles | `chat_sessions` | AI session grouping |
| `doctors` | Expert profile cards (bilingual) | `user_chat_models` | User-defined models |
| `appointment_records` | Booking orders | `chat_records` | AI counseling records (with vectors) |
| `expert_chat` | Counseling private chat | `user_memories` | RAG long-term memory |
| `psychological_tests` | Assessment scales (incl. expert-created) | `analysis_reports` | AI periodic reports |
| `test_questions` | Scale questions | `user_oauth` | OAuth bindings |
| `test_results` | Assessment results | `sensitive_words` | Moderation lexicon |
| `chat_reports` | Chat reports | | |

> Schema changes use **lazy migration** (missing columns / tables are added automatically on first access); existing deployments need no manual SQL.
